# Mock mode (for A1)

`make mock` starts the backend with `WAYKIN_MOCK=1` (no graph, no exposure data) and Vite on :5173.
Add `DEMO_MODE=1` (or use `make mock-demo`) to get the demo presets and `/api/demo/*`.

| Endpoint | In mock mode |
| --- | --- |
| `GET /api/meta` | `waykin/mocks/meta.json`, with live `relay_mode` and `demo_mode`; `demo_presets` only when `DEMO_MODE=1` |
| `GET /api/incidents` | `mocks/incidents.json`, category filter applied for real |
| `POST /api/routes` | picked by **`round(origin.lat × 10 000)` parity**: even (e.g. `53.5150`) → `routes_recommend.json`; odd (e.g. `53.5169`) → `routes_abstain.json` |
| `POST /api/routes/reroute` | always `routes_reroute.json`, which avoids the mock closure's edges |
| Journeys, relay | **real** (in memory), both e2ee and `RELAY_PLAINTEXT=1` |
| `WS /api/hazards/stream` | snapshot, then **15 s after connect** the fixture closure `mock-closure` (edges 54, 219), which sits on the abstain fixture's fastest route |
| `POST /api/hazards` | real; every hazard gets the fixture's edge ids. Needs `X-Admin-Token` (printed at startup) unless `DEMO_MODE=1` |
| `POST /api/demo/trigger/mock-reroute` | `DEMO_MODE=1` only: adds the same closure at once (no 15 s wait) and broadcasts it |
| `POST /api/demo/reset` | `DEMO_MODE=1` only: clears hazards, ends every journey |

Test the full reroute loop in mock mode: plan the `mock-reroute` preset (abstain fixture), start walking,
trigger the closure, see that the plan's `edge_ids` include a blocked edge, call reroute, and get the detour.
`backend/tests/api/test_demo_full_flow.py::test_full_demo_loop` does exactly this.

Fixtures are generated by `python -m waykin.mocks.make_fixtures` (from `backend/`): edit the generator, not the JSON.
